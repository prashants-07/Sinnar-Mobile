# Sinnar Mobile

A redesign of the existing Sinnar Mobile repository, preserving its Git history, business identity and original photographs. The public frontend uses HTML, CSS and ES modules. The backend uses Java 21, Spring Boot 3.5.16, Spring Security, JPA/Hibernate, Flyway and MySQL 8.

## What is included

- Eight static public pages: home, about, products, offers, repairs, FAQ, contact and enquiry privacy.
- A responsive store design with smartphone, wholesale, cover, accessories and smart-watch sections, WhatsApp enquiries, click-to-call, Google Maps and reduced-motion support.
- A database-driven catalogue with search, categories, sorting, pagination, optional prices, discounts derived from administrator-entered prices, availability and featured products.
- Administrator-managed offers, expiry dates, promotional banners, FAQs, contact details and business hours.
- Contact and repair forms that save requests in MySQL. Success is displayed only after the server saves the request.
- A session-authenticated dashboard at the **backend’s `/admin/` URL**, with CRUD, validated JPEG/PNG uploads, enquiry status changes and real database statistics.
- BCrypt passwords, ADMIN authorization, session fixation protection, CSRF tokens, restricted CORS, input validation, safe uploads, login/submission throttling and a honeypot.
- MySQL migrations, Maven wrapper, Docker configuration, verification workflow and a manually triggered GitHub Pages workflow.

No prices, availability, discounts, reviews, ratings, opening hours, repair guarantees or business achievements are invented. Demo products are opt-in (`SEED_DEMO=true`), visibly labelled and have no prices. An empty production catalogue is intentional until the administrator adds real listings.

Edit `frontend/` for normal development. Shared static page content is generated by `scripts/build_pages.py`; if editing an HTML page directly, do not regenerate it without incorporating those changes into that script. Keep the root output current with `python scripts/publish_static.py` when using branch-based Pages hosting.

## Local setup (Java 21 and MySQL 8)

1. Install JDK 21. Maven need not be installed: use `backend/mvnw.cmd` on Windows or `sh backend/mvnw` on macOS/Linux. The wrapper downloads Maven from Maven Central on its first run.
2. Create an empty database and a dedicated application user using [database/setup.sql](database/setup.sql). Replace its example password locally. Do not commit the edited file or real credentials. The application runs Flyway migrations automatically and Hibernate validates the schema.
3. Set environment variables in the shell used to launch the backend. `.env.example` is a reference; Spring does **not** load `.env` files automatically. Docker Compose loads `.env` for interpolation.

PowerShell, from the repository root:

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/sinnar_mobile?serverTimezone=UTC'
$env:DB_USERNAME = 'sinnar_app'
$env:DB_PASSWORD = Read-Host 'MySQL application password' -MaskInput
$env:ADMIN_USERNAME = Read-Host 'First administrator username'
$env:ADMIN_PASSWORD = Read-Host 'First administrator password (12+ characters)' -MaskInput
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:SEED_DEMO = 'false'
cd backend
.\mvnw.cmd spring-boot:run
```

`-MaskInput` requires PowerShell 7. On Windows PowerShell 5.1 use `Read-Host -AsSecureString` and `[System.Net.NetworkCredential]::new('', $secureValue).Password` to assign each password to the corresponding environment variable.

Open `http://localhost:8080/` for the full application and `http://localhost:8080/admin/` for the dashboard. For first startup, supply an administrator password of at least 12 characters and no more than 72 UTF-8 bytes. Only a BCrypt hash is stored. Credentials provision the first account only; changing these variables later does not reset it. Remove `ADMIN_PASSWORD` from the production environment after provisioning if your hosting workflow permits it.

To recover an existing account, set `ADMIN_USERNAME` to its exact stored username, set `ADMIN_PASSWORD` privately to the desired new password, and set `ADMIN_PASSWORD_RESET_ID` to a new identifier such as `recovery-1`. Redeploy/restart. Each identifier is applied only once per account; ordinary redeploys with the same ID do not reset it again. Remove the reset-ID variable after successful recovery. This is a hosting-operator action and has no public reset API. If the username is uncertain, inspect only the `username` column in `admin_users` through your secured database dashboard; do not delete the table or expose password hashes.

To preview the static frontend separately, from the repository root in a second terminal:

```powershell
python -m http.server 5500 --directory frontend --bind 127.0.0.1
```

Open `http://localhost:5500/`. Its default public configuration points to `http://localhost:8080`. The local profile allows origins `http://localhost:5500` and `http://127.0.0.1:5500`. Use the backend origin for admin sign-in. If using another port, update `API_BASE_URL` accordingly.

Without a connected backend, the store still shows factual business information, collection links, location and WhatsApp actions. Catalogue and offers show a clear unavailable state. Forms never pretend a message was saved.

## Tests and builds

From the repository root:

```powershell
python scripts/check_frontend.py
cd backend
.\mvnw.cmd -B -ntp verify
```

The Maven suite uses an isolated H2 database in MySQL mode by default. To test against an **empty disposable MySQL database**, set `TEST_DB_URL`, `TEST_DB_USERNAME`, `TEST_DB_PASSWORD` and `TEST_DB_DRIVER=com.mysql.cj.jdbc.Driver`, then run the same command. **Never point this test suite at production:** it clears test products, offers, banners and enquiries. CI supplies a disposable MySQL 8 service and Java 21.

Optional Windows QA helpers:

- `python scripts/bootstrap_tools.py`: downloads checksum-verified Maven and official wrapper scripts into ignored local tooling.
- `python scripts/mysql_qa.py`: starts a separate MySQL instance using the installed binaries, runs tests and shuts it down. It uses port 3307 and data under `.tools/`, and does not use the installed MySQL service.
- `python scripts/mysql_qa.py --serve`: also starts a disposable backend preview on port 9080. Press Ctrl+C to stop it.
- `node scripts/http_smoke.mjs`: verifies real HTTP integration against that disposable preview using the frontend Fetch module and test-only credentials.

Run the MySQL helper only in development. Its isolated database retains the suite’s test-only account. This account is never created by production migrations or production bootstrap.

For image optimization, install Pillow and run `python scripts/optimize_images.py`. Existing originals remain unchanged. See [image provenance](frontend/assets/images/README.md); the original repository does not include licence evidence for its photographs.

## Deploy frontend and backend separately

See [the deployment guide](docs/DEPLOYMENT.md). GitHub Pages serves the static frontend and cannot run Java or MySQL. Deploy the backend and MySQL first, then set `API_BASE_URL` to the backend HTTPS origin. Keep the administrator dashboard on that backend origin.

The frontend uses relative page and asset links, so it supports the existing `/Sinnar-Mobile/` project path and direct page refreshes. There is no client-side router or fallback rewrite requirement.
